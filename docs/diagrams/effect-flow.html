Effect flow — the core decides, the caller performs
can() answers with a verdict and a list of effects. Nothing inside packages/domain mutates state; the two appliers below are the only writers, and they read from the same list.
Call
packages/domain/src/note-machine/machine.ts
can(action, ctx) — one of 10 actions
generation.complete regenerate start_review return approve reject resubmit amend …
Context — everything the rules need
no globals, no clock
status · assignedReviewerId · approvedAt · actor {id, role}
now (ISO, caller-supplied) · reason · mfaVerified · source user | server
Pure evaluation — three steps, in order
findTransition(action, from)
Looks up the edge in the 11-row TRANSITIONS table. Missing edge means the action was never legal here.
guard(ctx)
Role, assignment, MFA, non-empty reason, 24h amend window. Returns a sentence on refusal, null to allow.
effects(ctx)
Builds the change as plain data. Reads ctx.now and ctx.actor; performs nothing.
Refused
{ ok: false, action, from, reason }
The reason is written to be read by a human. Web: disabled button plus tooltip — no request is sent. API: 409 transition_rejected carrying the same sentence, because the browser's verdict is only advisory.
Allowed
{ ok: true, action, from, to, effects: TransitionEffect[] }
to is the next status. Everything else that must change travels in effects — five variants, closed union.
Effect Emitted by Means
assign_reviewer(reviewerId) start_review (from READY_FOR_REVIEW, AMENDED) The actor takes ownership of the review.
release_reviewer return · approve · reject Ownership ends; the note is nobody's until claimed again.
record_approved_at(at) approve Stamps the clock the amend grace window is measured from.
clear_approved_at amend Reopens the note; the old approval no longer stands.
require_new_version resubmit · amend Content must continue on a fresh version row rather than overwrite a signed one.
the same array is handed to both sides
API — the write that counts
store.ts · applyEffects()
switch over effects → sets assignedReviewerId and approvedAt on the stored note.
status + updatedAt written from result.to.
require_new_version → branches a version row off the current head and emits note.version_added. The signed revision stays intact.
Appends the ReviewEvent, records the clientMutationId, emits note.status_changed.
Web — the optimistic guess
entities/note/lib/transition-patch.ts
same switch → resolves assignedReviewer and approvedAt into a patch object.
Returns { status, assignedReviewer, approvedAt, updatedAt }, or null if the core refused.
require_new_version is a deliberate no-op — only the server mints versions; the echo arrives over the socket.
Detail cache, list caches, and a local review row are patched from that one object; the pre-patch snapshot is the rollback.
Both switches are exhaustive over the union, so adding a sixth effect fails the build in the browser and the API until both learn to apply it — which is the whole reason the change is data instead of a function call.
